# M6.3 — backend переименования без замены назначения

## Контракт

`ramfs_rename`, `kvfs_rename`, `vfs_rename` переименовывают существующий
файл без перезаписи другого файла, без выделения нового тела и без
copy/delete fallback. Один и тот же существующий basename — no-op.
Несуществующий источник не превращает no-op в успех.

RAMFS сохраняет слот, указатель на тело и размер; заполненные 32 слота и
OOM не мешают переименованию. Только ограниченный RAM lookup/publication
сериализован сохранением IRQ flags; под запретом IRQ нет дисковых операций
или выделения памяти. Host-модель не исполняет привилегированное IRQ asm.

KvFS меняет только name существующей записи, сохраняя extent, size, flags
и reserved. Используется один существующий `commit_entry`: одна публикация
сектора каталога, без записи тела/superblock/других групп каталога. Новый
extent и свободный слот не нужны. Это не новая гарантия против torn-sector
или физической потери питания и не многопоточная транзакционная ФС.

Если запись metadata вернула ошибку, результат **неизвестен**: новое имя
могло уже попасть на диск. Mount немедленно fenced существующим механизмом,
автоматического rollback/retry нет. Нужны явный remount и проверка имени.
Нельзя обещать, что после такой ошибки источник остался под старым именем.

## Имена и ошибки

Один непустой basename: RAMFS максимум 23 байта, KvFS 39 байт. Проверка
ограничена размером поля; отвергаются `.`, `..`, slash/backslash, ASCII
control/DEL и отсутствие NUL в границах поля. Остальные байты сохраняются,
включая UTF-8, без Unicode/case normalization. Имя назначения копируется
до публикации: указатели, ссылающиеся на старое поле имени, безопасны.
VFS дополнительно отказывает пустым/NULL/незавершённым путям >=256 байт.

Ошибки **семейства rename**, а не общие legacy `kvfs_error`:

| Код | Значение |
|---|---|
| 0 | успех или existing same-name no-op |
| -1 | том/FS недоступны |
| -2 | read-only или callback rename не поддержан |
| -3 | источник отсутствует |
| -4 | неверное/слишком длинное имя либо путь |
| -5 | назначение существует; оно не заменено |
| -6 | исход публикации metadata неизвестен; mount fenced |
| -7 | разные тома; перенос не поддержан, copy/delete не вызывались |

Callback в `vfs_ops_t` необязателен. FAT и NTFS имеют NULL и отказывают
закрыто, включая writable opt-in FAT. Их остальные операции не меняются;
поддержка FAT/NTFS rename не заявлена.

## Доступность

Существующая shell-команда `mv`/`rename` теперь использует metadata rename:
два простых RAM имени либо два абсолютных VFS пути. Старое предварительное
удаление назначения и create/delete больше не используются. При конфликте
файлы не заменяются; cross-volume и uncertain outcome сообщаются отдельно.

Это **backend increment, не готовая мышиная команда**. Мышиный диалог с
snapshot identity и кнопками подтверждения/отмены — следующий M6.4.
