# M4.14 — native негативные STATUS/LINE/clock-pointer fixtures

Закрыт пробел M4.11–M4.13: не только host validation/положительная интеграция,
но и настоящий source-only MCC → CPL3 adapter fail-stop на BIOS32/UEFI64.
Production code не менялся после8cf7b2c; это расширение regression harness.

- STATUS с control byte1: service отвергает текст, adapter завершает user с
  `reason1/vector0/value33`, прежний private status не публикуется как успешный.
- LINE x0=-32769 за границей signed16: service отвергает, adapter завершает
  `reason1/vector0/value34` (не молча игнорирует ошибочную команду).
- clock(1048576,0,0): user-only adapter пытается записать H через недопустимый
  caller pointer и получает CPL3 `reason2/vector14`; ядро не пишет по этому адресу.
  Это проверка fault caller pointer, **не** нативный proof ветви exit35.
  Недоступный/invalid RTC cache и CLOCK output faults проверены host suite M4.13;
  physical unavailable RTC в native fixture не симулируется.
- Каждый новый случай освобождает process/pages: used_frames возвращается точно
  к baseline, desktop принимает следующий compile/run. Затем прежние heap/files
  limits, default legacy switch, GUI exit и private namespace checks — PASS.

Исходники берутся из REUSED_NATIVE_FAULTS в tests/mcc/isolated_source.py,
компилируются внутри гостя через измеренные widget hitboxes. Для каждого случая
переиспользуются quota.c/quota.kapp: RAMFS32 не расширен, spare file slots не нужны.
При неудаче assert включает имя fixture, diagnostic и проверку PMM, не retry.
