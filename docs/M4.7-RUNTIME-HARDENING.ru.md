# M4.7 — долгоживущий root, CPU policy, оконный lifecycle

Дата: 17.10.2026. Продолжение M4.5/M4.6, не публикация релиза.

## Реализация

- `ku_refresh`: под kernel CR3 и с выключенными IRQ обновляет только supervisor
  части private root/spine. Новые kernel/MMIO ancestors теперь видны следующему
  pump. User pages, их права, physical frames и pin не меняются. Замена borrowed
  spine/root отвергается целиком до записи; это не механизм смены kernel root.
  i386 также обновляет supervisor половину общего 12–16 MiB PT.
- Load/event/unload guards и очереди теперь сериализованы IRQ-off с самого входа.
  Ошибка `ks_post`, включая исчерпание token, снимает приложение fail-closed.
  Это single-core/single-GUI dispatcher, **не** SMP locking/multiple user tasks.
- В user policy выключены CR4.PCE и CR4.FSGSBASE; CR4 возвращается до kernel peers.
  Нативная x64 fixture сначала намеренно включает inherited FSGSBASE/PCE и
  проверяет #UD на WRFSBASE. Для каждой diagnostic fixture дополнительно
  проверяются возврат CR0/CR4, SYSENTER_CS/EFER, TSS stack, CR3 и PMM baseline.
- GUI явно подписывает legacy status строкой `Trusted/kernel` / `Доверенное/ядро`.
  Нельзя смешивать эту подпись с защищённым ABI4. Default compiler остаётся ABI3.
- SDK key `p` намеренно растягивает DRAW на 8 PIT ticks; это bounded test-пример,
  проверяющий, что отложенный DRAW не зависит от clip предыдущего GUI frame.

   MMIO ancestors, supervisor-only доступ, сохранность user data/pins и отсутствие

## Границы

Новый MMIO ancestor моделирован host walker, а не физическим hotplug-устройством.
Нет SMP/TLS/FPU context/float, persistent file grants или Workshop ABI4 target.
Следующий независимый increment — bounded text/graphics services для будущего
изолированного compiler runtime. ABI2/3 не изолированы; i386 без NX.
Save64 historical cause и hardware/TT/VBox/SATA gaps не закрыты.
