# M6.5 — безопасная замена в старой RAM-команде cp

Проверка старого `cmd_cp` обнаружила предварительное удаление назначения
до выделения памяти. При OOM терялся существующий target. Same-string cp
попадал в ту же destructive ветку для самого source.

Команда теперь использует существующий RAMFS allocate/copy-before-publish
`ramfs_write`, без delete/create. Existing same-name — no-op без выделения
памяти. Успешное копирование по-прежнему может заменить существующий
RAM target: это сохранённая явная shell-семантика cp, не новый no-replace
контракт. При ошибке существующий target и source остаются; ошибка сообщает
`target unchanged`. Код стал короче; нового copy backend/формата ФС нет.

## Проверки

- `m65-ramfs-red.log`: новый тест реальной старой команды воспроизвёл потерю
  target при forced OOM до исправления (ожидаемый assertion failure).
- `tests/mcc/test_ramfs_commands.c`: реальные utilcmds+RAMFS, ASan/UBSan,
  EN/RU. OOM сохраняет pointer/body target; same-name не выделяет; успешная
  COW замена и source retention; empty/missing/long name; full table +
  существующее/новое назначение. Заодно actual mv full-table/no-replace и
  cross-volume routing без copy/delete. После теста все buffers освобождены.
- `m65-host-targeted.log` и `m65-host-all.log` PASS: полный существующий host
  regression, включая новое включение shell test в target `ramfs`.
- `m65-release.log`: BIOS/i386+UEFI/x86-64, GRUB/direct ISO build PASS.
- `kvantos-m6-5-shell-copy-integrit-a23bc85a` exit0: `ramfs-command-smoke.py`
  BIOS32+UEFI64 на production diskless kernels PASS — настоящие команды
  cp samepath/overwrite/missing/long/empty/full-table и mv conflict/rename.
  Также существующий native rename metadata/cold-mount/EIO обеих архитектур
  PASS. Логи `m65-{commands,rename}-native.log` и отдельные result.json.

OOM/heap counters — host-only, native heap OOM не инжектируется.
Workshop/CPU/SDK full native были PASS непосредственно на M6.4; M6.5 их
повторно не заявляет. Изменён только RAM shell cp, не compiler/isolated ABI.
VFS shell `vcp` ещё требует отдельного exact-read/path/namespace increment.
Нет публикаций, физических дисков и hosted-CI qualification.
