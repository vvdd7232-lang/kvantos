# M4.13 — readonly cached CLOCK для ABI4

CLOCK=15 / QUERY cap64, protocol1. Остальные операции/offsets и старые images
не изменены; поля services добавлены в конец, status offsets прежние.

- Request40: a=output offset, b=20, c=d=token=0, flags=0, актуальная generation.
- Result20: пять u32 `{version=1,bytes=20,hour,minute,second}`. h0..23/m,s0..59.
  Возврат20, либо обычный checked-buffer fault; отсутствующий/невалидный snapshot
  даёт -8/AGAIN, без изменения output. Весь output preflighted до записи;
  request уже локально скопирован, собственный output может перекрывать request.
- Сервис не требует DRAW/event token и не расходует graphics quota. Цикл clock
  не делает I/O: действуют прежние quantum/resource limits, а не миллион CMOS polls.
- RTC модуль публикует last range-checked sample только после штатного rtc_read,
  с сохранением IRQ state; exhausted UIP guard/невалидный час не публикует cache.
  Clock/date writes инвалидируют его до следующего обычного read. Dispatcher
  копирует cached H/M/S перед входом CPL3; syscall только копирует bounded20B.
- Это best-effort cache последнего чтения RTC (GUI обновляет его штатно),
  не гарантированно свежий/синхронный hardware snapshot и не UTC/timezone/date API.
  Нет CMOS port access, kernel pointers или clock setters в user profile.
- Исправлен прежний RTC decode 12h: 12AM=0, 12PM=12. Проверены все 48 комбинаций
  binary/BCD × AM/PM × 1..12; invalid12h0/13 и UIP exhaustion инвалидируют cache.
  Формат записи RTC и physical RTC qualification этим не расширяются.
- User-only compiler adapter stages20B, проверяет version/bytes/ranges, затем
  пишет nullable/aliased outputs в порядке h,m,s, как legacy API. Неудача → exit35,
  а не поддельные нули/uptime. New adapter требует mask127; старые mask15/63 apps
  работают с новым ядром. Clock разрешён компилятором; beep/log ещё запрещены.
