# M6.12 — NTFS logical sectors → 512-byte block API

## RED и исправление

Actual `ntfs_read_sectors` получал NTFS logical-sector size 4096, но напрямую
передавал `count=1` в `disk_read`, чей контракт — число 512-byte blocks.
Ожидалось 8 блоков; RED assert завершился exit 134:
`/home/user/workspace-checkpoints/m612-ntfs-sector-red.c`,
`build/autonomous/m612-ntfs-sector-red.log`.

Теперь `ratio = bytes_per_sector / 512`; NTFS LBA/count переводятся в
512-byte LBA/count с overflow checks и чтением bounded batches до 64 blocks.
Смещение буфера считается в фактически прочитанных байтах. До I/O проверяются
границы logical volume, переданный размер 512-byte partition extent, абсолютный
device LBA и арифметика count. Probe/mount отвергают NTFS extent за известной
границей partition; нулевой partition size сохраняет прежнюю семантику
«extent неизвестен», не снимая внутреннюю NTFS total-sector guard.

Cluster read и MFT record arithmetic проверяют умножения, деление на ноль,
невалидное кратное record/cluster и секторное переполнение. NTFS logical
sector size принимается как 512/1024/2048/4096 байт; нижний block API остаётся
512 байт. Это не утверждение о физической геометрии 4Kn-устройства.

## Границы квалификации

Тестовые NTFS тома — synthetic adapter fixtures. Реальный NTFS образ пока не
смонтирован этой реализацией в qualification suite. Partition values берутся
из software parser, это не physical-media identification или hotplug generation.
Никаких NTFS write permissions, repair, rescan либо retry не добавлено.
Физические 4Kn devices, USB/SATA/TT, широкая NTFS interoperability, hosted CI и
публикация остаются OPEN. Последующая M6.13 limited qualification на реальных
regular-file images выявила и исправила отдельный 4Kn USA-stride issue; точные
пределы и matrix записаны в `docs/M6.13-NTFS-IMAGE-QUALIFICATION.ru.md`. Physical
media не используются.
