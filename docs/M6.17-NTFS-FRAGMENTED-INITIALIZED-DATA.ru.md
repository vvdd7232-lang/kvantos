# M6.17 — fragmented stream и NTFS Initialized Size

## Найденная граница безопасности

У неresident `$DATA` есть и logical file size, и initialized size. Раньше `read_attr`
использовал только logical size, поэтому участок файла после Initialized Size мог
прочитываться непосредственно из выделенных кластеров. NTFS требует выдавать нули
для неинициализированного хвоста; иначе при реальном reuse кластеров можно раскрыть
старые данные тома.

## Воспроизводимый fixture

Только private regular image, никакого host/FUSE mount:

1. ntfs-3g создаёт 512-byte-sector volume;
2. в `/fragmented.bin` записывается ровно один 4096-byte cluster с deterministic
   pattern;
3. `/blocker.bin` занимает следующий кластер;
4. `ntfsfallocate` добавляет целевому файлу диапазон до 1MiB;
5. `ntfsinfo` проверяет nonresident `$DATA`, logical size 1MiB и Initialized Size
   4096; `ntfscluster` независимо проверяет полный runlist из двух физических
   несмежных runs (256 кластеров суммарно);
6. setup помечает байты `0xA5` во всех allocated data-clusters после initialized
   prefix. Независимый `ntfscat` обязан вернуть исходный первый кластер + нули до
   EOF; если прочитать сырые allocated bytes напрямую, хвост не нулевой.

Таким образом проверяется и runlist traversal, и zero-fill по Initialized Size,
а не случайно нулевые freshly formatted clusters. Все writes/poison происходят
лишь при подготовке disposable regular-file image до запуска production adapter.
Adapter открывает её read-only; block-write=0 и SHA всего poisoned image не
меняется.

## Production fix и проверки

`kernel/ntfs.c:read_attr` считывает низшие 32 бита Initialized Size, отказывает,
если он больше размера файла, читает только инициализированный диапазон, а
оставшийся участок заполняет нулями. Резидентные атрибуты не затронуты.

`make -C tests/fs CC=gcc-12 ntfs-image` PASS: предыдущие raw sector 512/1024/2048/
4096 и MBR 512/4096 cases плюс настоящий 2-run fragmented stream. Poisoned data
проверены `ntfscat` и production adapter; RO/zero writes/no-OOB/full SHA PASS.
Тот же полный actual-image набор PASS под ASan/UBSan (host harness). Дополнительно
PASS `make -C tests/mcc CC=gcc vfs`, filesystem GPT22 + owned-WAL1696 recovery cuts
+ FAT perf, и clean `make CC=gcc-12 all`: BIOS32 kernel, UEFI64 kernel и EFI stub
успешно собраны. См. `build/autonomous/m617-*.log`.

QEMU/OVMF runtime regression на обновлённом kernel не выполнялась: в текущей
среде отсутствуют QEMU, GRUB ISO tools и OVMF; native runtime claims не добавляются.

## Точная граница квалификации

PASS для этого конкретного clean ntfs-3g fixture: один 1MiB unnamed/nonresident
`$DATA` с двумя physically non-adjacent runs, initialized prefix 4096 bytes и
poisoned allocated tail. Это не означает произвольные fragmented files, много
runs/extent records, sparse/compressed/encrypted data, GPT-offset, nested Unicode
directories, Windows/dirty volumes или физическую 4Kn совместимость. NTFS остаётся
read-only; физическое устройство не открывается.
