# M6.9 — EOF не означает ошибку или недоступный том

## Исправление контракта

Actual native adapter RED: после mounted=false KvFS readdir ошибочно возвращал
0 (EOF). Assert readdir==-1 упал exit134; тот же callback fixture после правки
PASS. Логи m69-unavailable-listing-{red,green}.log. M6.7 не мог распознать
ошибку, которую backend вообще не выдавал; эта оговорка теперь закрывается
для перечисленных ниже путей, не для произвольной повреждённой FS.

VFS readdir возвращает строго 1 entry / 0 clean EOF / -1 error. NULL output,
negative index, unknown mount, missing callback, invalid callback count и
смена namespace внутри callback — error. Ошибка больше не трактуется как
truthy row. Batch API также проверяет count/generation; generic fallback
не превращает ошибку после нескольких элементов в частичный success.
При -1 содержимое output/batch НЕ обещается неизменным: caller обязан
игнорировать его целиком. Это не buffer-atomic transaction и не новый lock.

- Native RAM/KvFS flat adapters отвергают не-каталог; KvFS отдельно проверяет
  mounted до listing. Доступный пустой корень остаётся clean EOF.
- FAT single wrapper больше не теряет negative результат уже существующего
  guarded batch API. Default RO/owned-WAL и все I/O fences сохраняются.
- NTFS listing проверяет resolve/walk_index и sticky read_error текущего
  запроса, в том числе скрытую ошибку чтения extension record при поиске
  optional attribute. Перед новым явным запросом flag очищается, без retry
  в прежнем запросе. Короткий read INDEX_ALLOCATION — error, а не EOF;
  нулевой/чрезмерный block size также отказывается. Read-only policy неизменна.
- Все kernel consumers проверены: FM уже strict и теперь сохраняет unloaded
  после явного Refresh недоступной KvFS; подпись «Список недоступен; обновите»
  отличается от «(пусто)». До действий — changed-or-unavailable guard.
  Shell vls проверяет status/namespace/bounded name и предупреждает, что
  вывод неполный, без ложного zero/success summary. Предварительный stat
  убран: его false мог сам означать I/O, а не «не каталог».
- Обновлены loops host harness/owned-WAL fixture: -1 больше не бесконечный
  поток старых строк. Форматы дисков и public ABI2/3/4 не менялись.

## Проверки

- ASan/UBSan actual native adapters: unavailable != clean EOF, unknown/NULL/
  index/non-directory, byte-count/rename прежние проверки.
- Actual FM/VFS: partial fallback error, namespace during callback и malformed
  count/generation direct batch; discard без смешанной публикации списка.
- Actual shell vls EN/RU: early/late error, namespace change, invalid count,
  empty/unterminated name, missing mount, bounded termination/no false count.
- Actual NTFS reader с маленькой synthetic resident MFT/index: valid entry,
  clean EOF/empty root, first-record read failure и fresh successful request,
  hidden extension-record read EIO, missing/file-not-directory. Только host,
  это не тест всех деревьев $INDEX_ALLOCATION/bitmap/ATTRIBUTE_LIST.
- Full host/GPT/owned-WAL/FAT-perf PASS, включая read-error cuts FAT list и
  12 batch read-EIO cuts без partial success и изменения образа. Production
  BIOS32/UEFI64 listing/namespace/state/vcp/Workshop/CPU/SDK PASS; listing
  также при 640×480. Все три runner exit0. Release/layout/11 apps PASS.
  Hosted CI и физические устройства не проверялись.
- После восстановления workspace M68 proof SHA и 451 source hash сверены:
  433 совпадают, 18 различий соответствуют pending M69, четыре новых M69
  файла сохранены. Scoped restore adc3a1b без reset/remote/protected chmod.
  Исходники сохранены отдельным recovery archive, все gates выполнены заново.

## Ограничения

Software single-owner namespace status не даёт physical hotplug/media identity,
atomic concurrent mutation либо гарантии против лживого/переписывающего память
callback. Уже выведенные shell строки не откатываются при позднем I/O:
показывается явное incomplete warning. Backend, скрывающий corruption как
нормальный EOF, всё ещё нельзя распознать автоматически. Глубокая hostile-
image qualification NTFS parser остаётся отдельным шагом; не объявляется
полной из-за этих двух status checks. Иные shell команды ещё используют
старый truncating sh_abs — следующий scoped increment, не исправлен M6.9.
Аппаратные USB/SATA/TT/FPU context и cross-volume move остаются OPEN.
