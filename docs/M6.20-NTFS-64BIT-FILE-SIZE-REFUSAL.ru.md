# M6.20 — отказ NTFS от размера файла с ненулевым high DWORD

## Найденная граница

VFS KvantOS передаёт размер файла через 32-битный тип, тогда как `$DATA` в NTFS
содержит 64-битные Real/Initialized Size. До исправления `read_attr()` и
`ntfs_op_size()` использовали только low DWORD. Воспроизводимый sparse-файл ровно
4 GiB имел low DWORD размера `0`, поэтому MFT/путь мог представлять его как
пустой файл. `$FILE_NAME` в проверочном образе также не сохранил high DWORD, так
что одной проверки directory index было недостаточно.

## Изменение

- `read_attr()` отвергает nonresident `$DATA`, если high DWORD Real Size или
  Initialized Size ненулевой; такой поток нельзя безопасно выразить текущим VFS.
- Проверка целевого MFT `$DATA` добавлена в разрешение пути и выдачу dirent:
  неподдерживаемый размер не становится доступен как нулевой/обрезанный файл.
- 64-битный размер из `$FILE_NAME` index тоже проверяется.
- `ntfs_op_size()` самостоятельно не возвращает low-word alias.
- NTFS остаётся только для чтения; поддержка файлов больше 4 GiB не заявляется.

## Воспроизводимая проверка

Создан частный 128 MiB regular-file образ через ntfs-3g; в него скопирован
небольшой непустой файл, затем `ntfstruncate` расширил его до `4294967296` байт
без соответствующего выделения данных. `ntfsinfo` подтвердил `$DATA` размер
`0x100000000` и отдельный Initialized Size. Проверка показывает важный край:
поля `$FILE_NAME`/index имеют low size и потому не могут быть единственным
источником размера.

Контроль RED собран с предыдущим committed `kernel/ntfs.c`: он провалил stat
(файл выдавался как будто обычный) и listing (не отказывался от непредставимого
размера). Исправленный production adapter: единственный смонтированный том RO,
`stat` и целевая запись каталога отказывают, чтение не выдаёт файл как данные;
OOB reads = 0, block writes = 0, SHA образа не меняется.

NTFS actual-image suite на 512/1024/2048/4096-byte logical sectors и существующий
двух-run/Initialized Size=1234 poison fixture прошли; MCC VFS/parser ASan/UBSan
прошёл, включая high-word synthetic index case. GPT/FAT и BIOS32/UEFI64/EFI
regressions — см. qualification log/proof archive. QEMU/OVMF runtime не запускался.

## Границы

Это отказ, а не 64-bit file support. Протестирован один regular-file 4-GiB sparse
fixture; произвольные большие/сжатые/зашифрованные потоки не квалифицированы.
Физические устройства, host mounts и NTFS writes/repair не использовались.
