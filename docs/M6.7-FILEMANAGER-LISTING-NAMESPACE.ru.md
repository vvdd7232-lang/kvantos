# M6.7 — список файлов принадлежит namespace, в котором он прочитан

## Контракт

Каждая панель сохраняет nonzero VFS generation, взятую ДО space/readdir.
Изменение generation в любом из этих callbacks, отрицательный или отличный
от 0/1 результат readdir, пустое либо незавершённое имя полностью отбрасывают
собранный список и cached space. Смешанный/частичный список не сортируется
и не считается загруженным. Граница прежняя: не более 512 записей на панель,
без новой heap allocation. Это не новый лимит строк редактора.

fm_listing_current проверяет loaded и stamp; getters количества/элементов/
space не отдают устаревшие данные. GUI не создаёт для них row hits и показывает
«Обновите список», а не «(пусто)». До preview, copy (обе панели), rename,
mkdir и delete проверяется актуальность исходного списка. Смена mount
между загрузкой панели и открытием действия больше не создаёт новый якобы
актуальный snapshot поверх старых имён. Up/Volume/Refresh остаются доступны;
явная перезагрузка списка даёт новый stamp.

Общий bounded join не позволяет длинному имени/пути превратиться в другое
имя после обрезки. Preview проверяет индекс, путь, результат read в пределах
0..4095 и namespace после чтения; неверный результат не открывает просмотр.
Уже открытый preview — снимок прочитанных байтов, не живое представление диска.

Delete confirmation сохраняет namespace/listing/pane и полный показанный путь.
Mouse Yes и клавиатурные Y/Enter проходят один guard: смена namespace, reload,
панели, выбранного пути или выбора отменяет запрос без remove. При смене
namespace внутри remove результат признаётся неизвестным независимо от
возвращённого кода; prompt закрывается, списки обновляются, retry отсутствует.
Источник не «восстанавливается» по предположению. Пользователь должен явно
переподключить и проверить диск перед новым действием.

## Проверки

- Actual FM/VFS host ASan/UBSan EN/RU: stale-before-open, stale destination
  copy без read/allocate, epoch внутри space и readdir, отрицательный callback
  после уже полученной строки, r=2, пустое/unterminated имя, скрытые stale
  getters/space, preview overcount/negative/read-time namespace, длинный путь
  и индекс за 512; delete snapshot после namespace/reload/pane/path/selection,
  Y/Cancel, неизвестное удаление с публикацией и без неё.
- Полный host suite (compiler, изолированные services/image/CPU policy,
  editors/RAM/VFS/storage/USB/AHCI), compiler mutations, GPT22 и normal-policy
  owned-WAL PASS: `m67-host-all.log`, `m67-fs-native-drivers.log`.
- Production BIOS32 + UEFI64, обычный режим и 640×480: remount через read-only
  Programs Check, исчезновение старых row hits, stale preview/copy/rename/
  delete/mkdir не записывают ни байта и не меняют RAM; Refresh восстанавливает
  действия. Старый delete prompt после remount не удаляет файл. Свежие rename,
  cancel delete и успешное delete сохраняют другие данные; cold boot проверяет
  persistence. Реальный blkdebug metadata EIO на delete снимает mounted,
  закрывает prompt и сообщает uncertainty; cold mount сохраняет исходный файл
  именно в этой prepublication injection. `m67-namespace[-small]-native.log`.
- Runtime Workshop / CPL3 CPU (три запуска на архитектуру) / SDK PASS.
- State/rename/copy regression BIOS32/UEFI64 PASS. Изначальный combined
  runner затем завершился exit2: ошибочное имя workshop-smoke.py, не kernel
  assertion. Ошибка сохранена в m67-native-chain-command-error.log; корректный
  runtime runner exit0, Workshop replay сохраняет отдельный финальный log.
- Release/layout/11 apps per architecture и checksums PASS; hosted CI не запускался.

## Границы

Это software namespace fencing, не lock/atomic multiwriter и не физическая
идентификация/квалификация hotplug. Для backend, который скрывает ошибку как
EOF (старый контракт некоторых VFS adapters), loader не может отличить их:
расширение truthful listing status остаётся отдельным шагом. В частности,
новая явная Refresh после KvFS fence ещё может получить legacy empty/EOF;
Programs/boot/shell M6.6 продолжают различать unavailable и пустую KvFS.
After-publication delete fault, malformed callback и mid-readdir generation
проверены только host-моделью, не объявлены нативными или аппаратными тестами.
Native EIO здесь — prepublication. FAT/NTFS rename/crossvolume move, TT recovery,
аппаратные USB/SATA и FPU context остаются OPEN. Remote/releases не менялись.
