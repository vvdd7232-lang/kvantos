# M6.10 — bounded shell paths и безопасный vcat

## Подтверждённые ошибки

Actual shell.c host fixtures до исправления:
- vcat size=7/read=8: запись terminating NUL за heap allocation, ASan RED exit1.
- vrm с CWD длиной 250 и относительным victim: truncating sh_abs вызывал remove
  с другим, обрезанным именем; assert(no remove) RED exit134.
Логи `m610-vcat-overcount-red.log`, `m610-truncated-remove-red.log`; исходные
fixtures сохранены в workspace-checkpoints. Оба прежних RED теперь GREEN.

## Реализация

Старый truncating sh_abs удалён. Один bounded sh_path для vls/vcat/vcp/vrm/
vmkdir/vcd проверяет абсолютный путь либо полный CWD/default /mnt join вместе
со slash и NUL. При отказе callback не вызывается; никакого усечения имени.
Прежний M6.8 copy resolver переиспользован, не дублируется. vcd .. сначала
проверяет CWD до vfs_parent; при generation change внутри stat CWD не меняется.
Семантика /mnt как synthetic directory не добавлена: прежний vcd .. с корня
volume по-прежнему может отказать и сохранить CWD.

vcat фиксирует generation перед stat и проверяет после stat/size/allocation/
read. До чтения/печати проверяется актуальность; требуется ровно requested
min(size,4096) байт. Negative/short/overcount/epoch не индексирует буфер и
не печатает полученное тело. Успешный preview остаётся ограничен 4096 байт,
пустой файл разрешён, buffers освобождаются. Read-only preview не объявляется
согласованным concurrent-file snapshot: generation не версия каждого write.

vrm/vmkdir сохраняют generation непосредственно перед единственной mutation.
Если backend меняет namespace, даже success code не считается доказанным:
вывод uncertainty/remount-and-inspect, без retry, rollback или предположения
о неизменности target. Обычные backend коды сохраняют прежний UX.

## Проверки

- Actual shell/VFS ASan/UBSan EN/RU: read negative/zero/short/exact/overcount/
  INT_MAX, epoch в stat/size/alloc/read, empty/OOM/no content on failure,
  long-CWD refusal для всех пяти команд без callback/allocation, remove/mkdir
  correct relative path, unknown mutation result, vcd namespace и invalid CWD.
  Включено в обычный make -C tests/mcc vfs, M6.8 copy tests сохранены.
- Production BIOS32/UEFI64: bounded shell path/vcat/vrm/vmkdir/vcd с реальным
  KvFS ATA image; read EIO не печатает файл, metadata delete EIO не сообщает
  success и сохраняет cold original. vcp повторно проходит samepath/relative/
  directory, read/flush/metadata EIO; listing status и stale namespace тоже
  regression PASS. Логи `m611-shell-path-native.log`, `m611-vcp-native.log`,
  `m611-listing-native.log`, `m611-namespace-native.log`.
- Full host/sanitizers/GPT/owned-WAL/FAT-perf/release/layout и runtime
  Workshop/CPL3 CPU PASS. SDK fixture `boxes32/64.kapp` отсутствовал при первом
  combined runtime runner (exit1, сохранённый `m611-sdk-initial-missing-fixture.log`),
  не test predicate/OS failure. После явного build all/runtime отдельный
  isolated-app replay создаёт i386/x64 result.json и печатает PASS; hashes
  kernel до/после SDK build совпали. Hosted CI не запускался.

## Границы

Не исправляет backend, который уже переписал буфер вне запрошенного размера.
Нет alias canonicalization, multiwriter lock, physical hotplug qualification,
новых разрешений записи FAT/NTFS, cross-volume move или автоматического retry.
Shell line budget 200 bytes сохранён: длинный накопленный CWD и malicious read
count проверяются host fixtures, не объявляются нативными вводами. Нет нового
лимита строк редактора. Hardware/TT/FPU context остаются OPEN.
