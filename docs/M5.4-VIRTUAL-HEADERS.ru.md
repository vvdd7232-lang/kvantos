# M5.4 — readonly virtual-header #include

Реализован ограниченный include для MCC в обоих targets: default ABI3/ring0 и
opt-in ABI4/CPL3. Это не полный CPP и не доступ к файлам SDK/ядра/дисков.

```c
#include <kvui.h>
#include "kvtypes.h" // повтор безопасен
void draw(void){
 kv_point p;p.x=KV_CHAR_W;p.y=KV_CHAR_H;
 clear(KV_BG);text(p.x,p.y,"Hello",KV_FG,KV_TRANSPARENT);
}
```

## Контракт

- Только три immutable строки в kernel/mcc_headers.h: kvui.h, kvkeys.h, kvtypes.h.
  Имена literal, case-sensitive, в `"..."` или `<...>`, длиной 1..31.
  Whitelist lookup не вызывает filesystem I/O и не возвращает kernel pointers.
- kvkeys.h: KV_KEY_UP/DOWN/LEFT/RIGHT=0x100..0x103, ENTER=10, ESC=27,
  BKSP=8, TAB=9, KV_CHAR_W=8, KV_CHAR_H=16.
- kvtypes.h: kv_int=int, kv_byte=char, kv_point — struct с int x,y (sizeof=8
  на i386/x64). Это не stdint/ISO unsigned/size_t и не aggregate-by-value ABI.
- kvui.h включает оба и задаёт KV_BG=0x182032, KV_FG=0xe6f0ff,
  KV_TRANSPARENT=-1. Все вместе расходуют 13 из 32 macro slots, 3 aliases,
  1 struct tag из обычных таблиц. Функции API уже известны MCC без заголовков.
- Каждый header подключается один раз за compile; active-stack проверяется
  раньше include-once. Цикл — ошибка, а не молчаливый skip. Вложенность <=4.
  Production graph имеет только 2 уровня; заведомо циклические/глубокие fixtures
  доступны исключительно в отдельном MCC_PP_TEST_HEADERS host binary.
- Пути, escapes, macro filenames и неизвестные заголовки отвергаются. После имени
  только whitespace или // / однострочные /* */ comments. Общие #if/#undef,
  function macros, line continuation и multiline directive comments не добавлены.
- Объём текстов headers учитывается в общем PP_WORK=64000. Макросы по-прежнему
  имеют depth8/body255; PP_OUTPUT=32000, source16000, CODE24000, DATA8000 сохранены.
  Нет динамического filesystem recursion/heap allocations.
- Newlines скрытых заголовков становятся whitespace: ошибки относятся к строке
  исходного редактора. Ошибки внутри header при расширении — строка include.
  Include/macro state сбрасывается перед каждым compile. При отказе size=0,
  caller output нетронут (проверено и после cycle/depth errors).

## Software verification

- `make -C tests/mcc CC=gcc-12 check includes isolated sanitize sanitize-isolated user-space user-service user-image`
  PASS: 301 legacy execution/codegen checks/arch; 23 isolated layout/validator/
  capacity/API/reset checks/arch (последние include cases — отдельный final log).
- `includes`: ASan/UBSan, обе architecture modes, production parser с отдельным
  test-only registry: include-once, цикл, depth4 accepted/depth5 rejected,
  shared work/output guards, source-row mapping, output atomicity/reset.
- Deterministic fuzz: 40000 mutations/arch/target (ABI3 и ABI4), включая valid,
  duplicate, malformed/path headers, ASan/UBSan PASS.
- NORMAL `make -j2 CC=gcc-12 release` PASS, freestanding i386/x64 linked.
- Native QEMU BIOS32/UEFI64: source-only fixture действительно компилируется
  внутри ОС с nested headers и повтором kvtypes.h; ожидаемый `41:2:ff:ok:A`,
  private LIST/розовая clipped LINE, heap/files, resource/CPU faults, PMM cleanup
  PASS. Legacy switch также компилирует источник с kvui.h/kv_point.
- Независимые native CPU и isolated SDK GUI regressions обеих архитектур PASS.
  Логи build/autonomous/m54-*.log; это software proof, не physical qualification.

Default Workshop/11 apps не переведены в CPL3. Storage Save64/TT recovery,
физические USB/SATA/VBox, FPU/float остаются OPEN; публикации нет.
