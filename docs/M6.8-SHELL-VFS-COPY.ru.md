# M6.8 — shell vcp не записывает неполное чтение

## Подтверждённая регрессия и исправление

До исправления actual cmd_vcp при size=7/read=3 вызывал write(size=3).
Host RED завершился assert(writes==0), exit134, без физического I/O:
`build/autonomous/m68-vcp-short-read-red.log`. После исправления тот же
тест PASS (`m68-vcp-short-read-green.log`). Это не новая copy-delete команда.

vcp теперь проверяет полный абсолютный/относительный путь до любых VFS
операций. Учитываются CWD либо /mnt, slash и terminating NUL. Directory target
сохраняет basename источника только если join целиком помещается в 256 байт;
обрезанный путь никогда не используется. Существующий sh_abs других shell
команд этим increment не меняется. . и .. basename при directory target
не принимаются; канонизация aliases не добавлена.

Namespace фиксируется перед stat. Смена при source/target stat, size,
allocation или read не позволяет перейти к write. Source должен быть файлом;
same-string final source/target (включая directory join) — unchanged/no-op
без size/read/heap allocation, также на RO томе. RO target либо отсутствующий VFS mount
отказывается до size/read/allocation. Верхний copy budget остаётся 4 МиБ.

Для записи требуется read == запрошенный полный size. Отрицательный,
короткий и чрезмерный результат освобождают буфер и НЕ вызывают write.
Пустой файл допускает read=0/write=0 с существующей VFS byte-count семантикой.
Source никогда не удаляется. Перед write нет удаления старого target.

Write считается успешным только при точном byte count и прежнем namespace.
Partial/overcount либо namespace change не выводят Copied; пользователь
получает source-kept/inspect-target, без retry и обещания, что target остался
неизменным. Backend ошибки/место/RO продолжают возвращаться явно. Общая
неизвестная ошибка записи тоже предлагает проверить target.

## Доказательства

- Actual shell.c + vfs.c, ASan/UBSan, EN/RU: negative/short/overcount read,
  namespace в обоих stat/size/alloc/read/write, OOM/RO/unavailable/missing,
  samepath и samepath-after-directory-join без allocation/read, empty, 4 МиБ
  limit, absolute/CWD/nonterminated bounds, exact 255-byte synthetic path,
  directory joins на границе 256, partial/negative/overcount/unknown write,
  одна попытка и освобождение буферов. Target не изменяется при prewrite
  отказах. test_shell_vcp входит в обычный make -C tests/mcc vfs.
- Whole-shell host TU содержит старые unrelated paging pointer casts;
  только эти две cast warnings исключены из host fixture, unused functions
  удалены linker gc-sections. Остальные warnings — errors; тест не заменяет
  cmd_vcp копией алгоритма. Production flags не ослаблены.
- Full host/compiler mutations/GPT22/normal owned-WAL и release/layout/11
  apps per architecture PASS: m68-host-all.log, m68-fs-native-drivers.log,
  m68-layout.log. Production Workshop/CPU/SDK обеих архитектур PASS.
- Actual shell BIOS32/UEFI64: binary KvFS→RAM→KvFS, relative/CWD и directory
  target, samepath whole-image SHA unchanged, source retention, empty copy,
  invalid KvFS name refusal и cold persistence PASS. Реальные ATA read EIO,
  body flush EIO и metadata write EIO: нет ложного Copied, RAM/source retained,
  старый published target сохраняется именно в этих prepublication injections;
  metadata namespace fence и cold remount PASS (m68-vcp-native.log).
- RAM cp/mv и mouse copy regression BIOS32/UEFI64 PASS; native copy runner
  exit0/M68_COPY_NATIVE_PASS. Host и runtime runners тоже exit0. Hosted CI
  не запускался.

## Границы

Это parity shell vcp с проверенным single-owner copy path, не атомарный
multiwriter snapshot содержимого. VFS namespace меняется при remount/fence,
не при каждой модификации файла. String identity — не канонизация aliases и
не physical media identity. Совпавший count не исправляет ошибочный backend,
который записал за границей буфера или солгал об операции. Native RO/OOM,
long-CWD и malformed byte-count injection пока host-only. FAT/NTFS writes
остаются под прежними RO/opt-in/WAL guards; xHCI/NVMe, hardware, TT cleanup,
FPU context и cross-volume move не реализованы этим шагом. Publication нет.
