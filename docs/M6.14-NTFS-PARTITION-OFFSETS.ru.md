# M6.14 — NTFS MBR partition offset и end-boundary fixtures

## Тестовая геометрия

Расширен `tests/fs/test_ntfs_image.py` и `make -C tests/fs ntfs-image`:
поверх реальных ntfs-3g regular-file volume fixtures строится MBR-образ — также
обычный private regular file. Единственный partition entry type 0x07 начинается
на LBA 2048 в единицах 512-byte block API; NTFS volume bytes копируются в этот
extent. Raw NTFS volume продолжает отдельно проверяться на 512/1024/2048/4096
logical bytes per sector. Offset path проверен для NTFS 512 и 4096 bytes/sector.

Production VFS autoscan/harness обязан сохранить `lba_start=2048`, смонтировать
`hda1` только для чтения, выдать root listing + точные bytes `proof.txt`, отказать
в write/remove/mkdir, выдать 0 write callbacks и оставить SHA всего MBR image
неизменным. Это actual MBR parser + block layer + NTFS adapter, не тест `ntfscat`
в одиночку.

Второй вариант портит размер MBR partition на один 512-byte block за концом
regular-file image. Он обязан отказаться монтировать NTFS и не переинтерпретировать
MBR как raw volume; host block callback не получает out-of-range read, writes=0.
Синтетический M6.12 partition test остаётся, а этот fixture проверяет реальную
цепочку вызовов с partition offset.

## Результат

Для 512- и 4096-byte NTFS logical sectors: actual image, valid MBR offset 2048,
read/list/RO/no-write/SHA checks PASS; malformed end extent отказан до чтения.
Для 1024/2048 raw-superfloppy fixtures M6.13 checks остаются PASS.
Все образы находятся под `tests/fs/build/ntfs-image-*` temporary directory и
удаляются по завершении; сценарий не читает/монтирует `/dev`, host filesystem
или физические носители.

## Scope OPEN

На момент M6.14 квалифицирован только ntfs-3g clean-volume fixture с маленьким
root file. Позднее M6.15 добавил крупный nonresident Unicode root file; его границы
описаны отдельно. Не проверены GPT-offset NTFS, несколько MBR partitions,
Windows-generated/dirty volumes, deliberately fragmented/multi-run data,
nested Unicode directory tree, compression, sparse files, host/hardware hotplug
или физические 4Kn устройства. NTFS остаётся read-only.
