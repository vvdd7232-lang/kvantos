# C-мастерская внутри KvantOS

Откройте **C-мастерскую** одним щелчком по значку или через меню **КВАНТ → C-мастерская**.
Это встроенный редактор и небольшой компилятор C в машинный код **i386 или x86-64**,
в зависимости от запущенного ядра.
Сборка выполняется самой ОС: ей не нужны GCC, Python, сеть или другой компьютер.
Готовый файл — обычный `.kapp` формата 1, ABI 3, совместимый с менеджером программ.

32-битная BIOS-сборка создаёт 32-битные `.kapp`, 64-битная UEFI-сборка —
64-битные. Указатели имеют ширину текущей архитектуры; `int` в обоих случаях
остаётся 32-битным. Исходник можно переносить между сборками и пересобирать;
готовый `.kapp` нельзя запускать в ядре другой разрядности.

## Быстрый старт

1. Щёлкните **C-мастерскую**. Появится готовый пример `hello.c`.
2. Кнопка **«Собрать»** создаст `hello.kapp`, статус покажет его размер.
3. Кнопка **«Запуск»** заново соберёт текущий текст и запустит его. Щёлкайте
   внутри окна: обработчик C будет перемещать квадрат.
4. Закройте приложение крестиком. Вернуться в мастерскую можно через панель
   окон или меню КВАНТ. Для выхода в консоль выберите соответствующий пункт меню.

**Справка** открывает памятку с собственной кнопкой **«Закрыть справку»**.
**Открыть** показывает файлы `.c`: выберите RAM или Диск/KvFS, щёлкните файл и
нажмите **Открыть**. Длинный список прокручивается колесом и кнопками ^/v.
**Сохранить** записывает текущий файл, для нового предлагает имя.
**Сохранить как** позволяет изменить имя; существующий другой файл заменяется
только после подтверждения. В имени можно поставить курсор мышью и печатать.
**Создать**, открытие, крестик и выход защищены диалогом
**Сохранить / Не сохранять / Отмена**, если есть несохранённые изменения.

В тексте щелчок ставит курсор, протяжка выделяет, протяжка за край прокручивает.
Кнопки **Копия / Вырезать / Вставить / Отмена / Всё** доступны мышью. Буфер
обмена общий с Блокнотом, документы и отмена независимы. Отмена одношаговая;
повторное нажатие возвращает отменённую правку. Вертикальная и горизонтальная
полосы перетаскиваются; колесо прокручивает вертикально, Shift+колесо — горизонтально.
Прокрутка не перемещает курсор. Русский текст в UTF-8 выделяется и удаляется по символам.

Клавиатура остаётся для текста и **необязательных** сочетаний: Ctrl+C/V/X/A/Z/S,
Ctrl+O/N/W, F5 (сборка), F6 (пуск), F1 (справка), F2 (диалог открытия).
Стрелки, Home/End, Delete, Backspace, Enter и Tab редактируют текст; Shift+стрелки
выделяют. В поле имени Ctrl+U очищает имя, Enter подтверждает, Esc отменяет.
Esc в редакторе снимает выделение, а не закрывает окно. Одиночные B/G/E больше
не используются для запуска окон. В играх клавиатурное управление сохранено.
Предел документа: 128 строк по 120 **байт**. Превышение лимита не обрезает текст,
неудачная вставка/склейка/загрузка оставляет документ нетронутым.

## Импорт исходников с FAT32-флешки (новая preview-сборка)

**Импорт → Обновить → папка → файл → Импорт** переносит `.c`/`.C` в RAM
без создания KvFS-образа на другом компьютере. Локальное имя можно изменить
перед подтверждением; затем **Сохранить / Собрать / Запуск** работают как обычно.
Флешка не изменяется. UTF-8 BOM и CRLF поддерживаются, двоичные файлы и
превышения лимитов отклоняются без потери текущего документа.
**USB UHCI и high-speed EHCI**, без OHCI/xHCI/хабов; в опубликованной 3.1.2 этой
кнопки ещё нет. **GPT + FAT32 поддерживается только для чтения**; преобразование
разметки не требуется. [Полная инструкция](../USB-IMPORT.ru.md).

## Где сохраняются файлы

* Без смонтированной **KvFS** исходник и результат находятся только в RAM.
  В статусе явно написано, что они исчезнут после перезагрузки.
* Если **KvFS смонтирована**, мастерская сохраняет и `.c`, и `.kapp` в RAM
  и на диск. Ошибка диска не считается успешной сборкой для запуска.
* После перезагрузки откройте мастерскую, нажмите **Открыть → Диск / KvFS**,
  выберите сохранённый исходник и щёлкните **Открыть**. Вводить имя не обязательно.
* Диалог показывает `.c` на выбранном носителе. Готовые `.kapp` видны в «Программах».
* Длина основы имени — до 18 символов, например `hello.c` → `hello.kapp`.
  Это плоские имена файлов, а не пути VFS. Сохранение прямо на FAT32/NTFS
  из этой первой версии мастерской не реализовано.

Для сохранения нужен поддерживаемый **IDE/ATA PIO** диск. AHCI/SATA и NVMe
драйверов пока нет. В QEMU q35 подключайте отдельный `piix3-ide` контроллер,
как в примере UEFI-запуска в RELEASE.ru.md; обычный `-drive if=ide` на q35
подключает SATA/AHCI, и система не увидит такой диск.

Кнопка «Запуск» (или F6) всегда компилирует текущий текст. Если в нём ошибка, старый `.kapp` может
оставаться на диске, но мастерская не выдаёт его за новый и не запускает.
Ошибка содержит номер строки; курсор переходит к ней.

## Пример

```c
int count = 0;

void draw(void) {
    clear(rgb(24, 32, 50));
    text(20, 20, "My C application", rgb(230, 240, 255), -1);
    fill(20 + count * 12, 90, 40, 40, rgb(60, 160, 240));
}

void click(int x, int y, int button) {
    count = (count + 1) % 20;
}
```

Мастерская сама создаёт `kapp_main`, таблицу обработчиков, описание окна
480×300 и заголовок `.kapp`. Заголовок окна берётся из имени исходника.
Вызывайте API как обычные функции — не через `sys->...`, без `#include`.

### Обработчики

| Функция | Когда вызывается |
|---|---|
| `void open(void)` | При открытии окна; `int main(void)` может заменить `open` |
| `void draw(void)` | Отрисовка кадра |
| `void key(int k)` | Нажатие клавиши |
| `void click(int x, int y, int button)` | Щелчок в координатах клиентской области |
| `void tick(void)` | Перед отрисовкой кадра |
| `void close(void)` | При выгрузке `.kapp` загрузчиком |

Достаточно определить `draw` или `main`; остальные функции необязательны.
В одной программе можно определять вспомогательные функции, в том числе
после вызывающего кода; поддерживается рекурсия. Стандартной `libc` нет.

### Встроенный API

Имена и порядок аргументов соответствуют полям `kv_api_t` в `include/kvapp.h`:

* Графика: `width`, `height`, `rgb`, `clear`, `pixel`, `fill`, `rect`, `line`,
  `text`, `text_width`, `status`.
* Время/звук: `ticks`, `hz`, `seconds`, `delta_ms`, `clock`, `beep`.
* Память/строки: `alloc`, `release`, `mem_set`, `mem_copy`, `str_len`,
  `str_cmp`, `str_copy`, `format`.
* Файлы KvFS: `file_read`, `file_write`, `file_delete`, `file_list`, `file_exists`.
* Остальное: `random`, `log`, `lang` (0 — английский, 1 — русский).

Например, `text(x, y, "UTF-8 text", foreground, -1)` рисует текст с прозрачным
фоном. `rgb(r,g,b)` создаёт цвет в формате текущего видеорежима.
`format(buffer, size, "Count: %d", value)` форматирует строку в заранее
выделенный буфер. Буфер можно получить через `alloc(64)` и вернуть `release`.

## Поддерживаемое подмножество C

* 32-битный `int`, знаковый `char`, `void`, указатели; `const` распознаётся,
  но его запреты на запись не проверяются. Арифметика целых — знаковая.
* Глобальные переменные с числовым/строковым литералом или нулевой
  инициализацией; локальные переменные, параметры, объявления через запятую.
* Именованные параметры, определения и прототипы функций.
* `if/else`, `while`, `for`, `return`, `break`, `continue`, блоки.
* `+ - * / %`, сравнения, `& | ^ ~ << >>`, `! && ||`, присваивание,
  `+= -= *= /= %=`, префиксные и постфиксные `++ --`.
* Адрес `&variable`, разыменование `*pointer`, индексирование `pointer[i]`,
  арифметика указателей. **Объявлений массивов нет**.
* Строковые и символьные литералы, escape-последовательности `\n \r \t \0
  \\ \" \'`, комментарии `//` и `/* ... */`.

**Это не полный ISO C и не GCC/TinyCC.** Нет препроцессора, `typedef`,
`struct/union/enum`, `static/extern`, `unsigned/long`, чисел с плавающей точкой,
массивов в объявлениях, приведений типов, `sizeof`, `switch`, `do/while`,
оператора `?:`, указателей на функции, внешних библиотек и объектных файлов.
Проверка типов ограничена; компилятор не является статическим анализатором.
Примеры существующего внешнего SDK с `sys->...` напрямую не собираются.
Для них остаётся обычная сборка GCC через `sdk/Makefile` на компьютере.

### Ограничения

Исходник: 16 000 байт; редактор: 128 строк по 120 байт. Код: 24 000 байт,
данные: 8 000 байт; файл вместе с заголовком укладывается в 32 КиБ.
До 8 аргументов, 256 символов (включая API), 128 записей локальных переменных,
512 байт (i386) или 1024 байта (x86-64) локального стека на функцию, 8 вложенных циклов, 24 уровня
вложенности парсера. Литерал — до 511 байт. При превышении — ошибка сборки.

## Безопасность

Как и другие `.kapp` KvantOS, результат работает в **ring 0**. Нативный код
не изолирован от ядра. Произвольный указатель, повреждение памяти,
глубокая рекурсия или бесконечный цикл могут повесить/уронить ОС.
Защита от некоторых исключений не превращает приложения в песочницу.
Сохраняйте исходники перед запуском экспериментов и используйте QEMU
с копией диска. Безопасность парсера не означает безопасность программы.

## Проверка реализации

* `make -C tests/mcc check`: по 73 проверки с исполнением сгенерированного
  i386- и x86-64-кода в Unicorn (нужно `python3 -m pip install unicorn`).
  В 64-битных проверках стек выше 4 ГиБ; проверяются сохранность регистров,
  выравнивание SysV-вызовов, указатели, рекурсия и аргументы на стеке.
* `make -C tests/mcc sanitize ramfs`: по 40 000 мутаций исходника для каждого
  backend под ASan/UBSan и атомарное сохранение RAM-файла при нехватке памяти.
* `python3 tests/mcc/smoke.py`: для BIOS/i386 и UEFI/x86-64 отдельно — сборка
  и запуск в ОС, нативный обработчик щелчка, независимость редакторов,
  ошибка сборки, открытие с KvFS после перезапуска, работа без диска.
  Дополнительно в гостевой ОС проверяются локальные переменные, двойные
  указатели, выделение памяти, функция с 8 аргументами и вариативный `format`.
  Стенд пишет только свои диски `tests/mcc/build/{bios32,uefi64}/workshop.img`.
