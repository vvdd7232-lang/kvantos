# C-мастерская внутри KvantOS

Откройте **C-мастерскую** одним щелчком по значку или через меню **КВАНТ → C-мастерская**.
Это встроенный редактор и небольшой компилятор C в машинный код **i386 или x86-64**,
в зависимости от запущенного ядра.
Сборка выполняется самой ОС: ей не нужны GCC, Python, сеть или другой компьютер.
Готовый файл — обычный `.kapp` формата 1, ABI 3, совместимый с менеджером программ.

32-битная BIOS-сборка создаёт 32-битные `.kapp`, 64-битная UEFI-сборка —
64-битные. Указатели имеют ширину текущей архитектуры; `int` в обоих случаях
остаётся 32-битным. Исходник можно переносить между сборками и пересобирать;
готовый `.kapp` нельзя запускать в ядре другой разрядности.

## Быстрый старт

1. Щёлкните **C-мастерскую**. Появится готовый пример `hello.c`.
2. Кнопка **«Собрать»** создаст `hello.kapp`, статус покажет его размер.
3. Кнопка **«Запуск»** заново соберёт текущий текст и запустит его. Щёлкайте
   внутри окна: обработчик C будет перемещать квадрат.
4. Закройте приложение крестиком. Вернуться в мастерскую можно через панель
   окон или меню КВАНТ. Для выхода в консоль выберите соответствующий пункт меню.

**Справка** открывает памятку с собственной кнопкой **«Закрыть справку»**.
**Открыть** показывает файлы `.c`: выберите RAM или Диск/KvFS, щёлкните файл и
нажмите **Открыть**. Длинный список прокручивается колесом и кнопками ^/v.
**Сохранить** записывает текущий файл, для нового предлагает имя.
**Сохранить как** позволяет изменить имя; существующий другой файл заменяется
только после подтверждения. В имени можно поставить курсор мышью и печатать.
**Создать**, открытие, крестик и выход защищены диалогом
**Сохранить / Не сохранять / Отмена**, если есть несохранённые изменения.

В тексте щелчок ставит курсор, протяжка выделяет, протяжка за край прокручивает.
Кнопки **Копия / Вырезать / Вставить / Отмена / Повтор / Всё** доступны мышью. Буфер
обмена общий с Блокнотом, документы и истории независимы. «Отмена» и «Повтор»
раздельные; клавиатурные варианты — Ctrl+Z и Ctrl+Y. До 64 правок в пределах
128 КиБ удалённого/вставленного текста на редактор. Крупная замена может
вытеснить старые записи раньше. Новая правка после отмены отбрасывает redo.
Отмена/повтор к сохранённой версии снимают `*`; ошибка сохранения не меняет
точку сохранения. Ввод одного символа пока считается отдельной правкой.
Вертикальная и горизонтальная
полосы перетаскиваются; колесо прокручивает вертикально, Shift+колесо — горизонтально.
Прокрутка не перемещает курсор. Русский текст в UTF-8 выделяется и удаляется по символам.

Клавиатура остаётся для текста и **необязательных** сочетаний: Ctrl+C/V/X/A/Z/Y/S,
Ctrl+O/N/W, F5 (сборка), F6 (пуск), F1 (справка), F2 (диалог открытия).
Стрелки, Home/End, Delete, Backspace, Enter и Tab редактируют текст; Shift+стрелки
выделяют. В поле имени Ctrl+U очищает имя, Enter подтверждает, Esc отменяет.
Esc в редакторе снимает выделение, а не закрывает окно. Одиночные B/G/E больше
не используются для запуска окон. В играх клавиатурное управление сохранено.
**После 128 строк — только предупреждение**, а не запрет. Импорт,
редактирование, отмена/повтор, сохранение и сборка/запуск работают и дальше.
Янтарная надпись рядом с именем не затирает сообщения об ошибках или сохранении.
Текст хранится упакованно, без отдельного ограничения количества строк:
входной файл и нормализованный текст — **меньше 64 КиБ**, строка — до 120
**байт**, а не символов. Переполнение не обрезает текст, неудачная
вставка/склейка/загрузка оставляет документ нетронутым.
У компилятора по-прежнему свой предел исходника — 16000 байт. Более длинный
текст можно редактировать и сохранять; при сборке будет понятная ошибка,
документ не изменится.

## Импорт исходников с FAT32-флешки (3.1.3)

**Импорт → Обновить → папка → файл → Импорт** переносит `.c`/`.C` в RAM
без создания KvFS-образа на другом компьютере. Локальное имя можно изменить
перед подтверждением; затем **Сохранить / Собрать / Запуск** работают как обычно.
Флешка не изменяется. UTF-8 BOM и CRLF поддерживаются, двоичные файлы и
превышения лимитов отклоняются без потери текущего документа.
**USB UHCI и high-speed EHCI**, без OHCI/xHCI/хабов; включено в 3.1.3; в старой 3.1.2 этой кнопки нет. **GPT + FAT32 поддерживается только для чтения**; преобразование
разметки не требуется. [Полная инструкция](../USB-IMPORT.ru.md).

## Где сохраняются файлы

* Без смонтированной **KvFS** исходник и результат находятся только в RAM.
  В статусе явно написано, что они исчезнут после перезагрузки.
* Если **KvFS смонтирована**, мастерская сохраняет и `.c`, и `.kapp` в RAM
  и на диск. Ошибка диска не считается успешной сборкой для запуска.
* После перезагрузки откройте мастерскую, нажмите **Открыть → Диск / KvFS**,
  выберите сохранённый исходник и щёлкните **Открыть**. Вводить имя не обязательно.
* Диалог показывает `.c` на выбранном носителе. Готовые `.kapp` видны в «Программах».
* Длина основы имени — до 18 символов, например `hello.c` → `hello.kapp`.
  Это плоские имена файлов, а не пути VFS. Сохранение прямо на FAT32/NTFS
  из этой первой версии мастерской не реализовано.

Для сохранения нужен поддерживаемый **IDE/ATA PIO** диск. AHCI/SATA и NVMe
драйверов пока нет. В QEMU q35 подключайте отдельный `piix3-ide` контроллер,
как в примере UEFI-запуска в RELEASE.ru.md; обычный `-drive if=ide` на q35
подключает SATA/AHCI, и система не увидит такой диск.

Кнопка «Запуск» (или F6) всегда компилирует текущий текст. Если в нём ошибка, старый `.kapp` может
оставаться на диске, но мастерская не выдаёт его за новый и не запускает.
Ошибка содержит номер строки; курсор переходит к ней.

## Пример

```c
int count = 0;

void draw(void) {
    clear(rgb(24, 32, 50));
    text(20, 20, "My C application", rgb(230, 240, 255), -1);
    fill(20 + count * 12, 90, 40, 40, rgb(60, 160, 240));
}

void click(int x, int y, int button) {
    count = (count + 1) % 20;
}
```

Мастерская сама создаёт `kapp_main`, таблицу обработчиков, описание окна
480×300 и заголовок `.kapp`. Заголовок окна берётся из имени исходника.
Вызывайте API как обычные функции — не через `sys->...`; `#include` для API не нужен.

### Обработчики

| Функция | Когда вызывается |
|---|---|
| `void open(void)` | При открытии окна; `int main(void)` может заменить `open` |
| `void draw(void)` | Отрисовка кадра |
| `void key(int k)` | Нажатие клавиши |
| `void click(int x, int y, int button)` | Щелчок в координатах клиентской области |
| `void tick(void)` | Перед отрисовкой кадра |
| `void close(void)` | При выгрузке `.kapp` загрузчиком |

Достаточно определить `draw` или `main`; остальные функции необязательны.
В одной программе можно определять вспомогательные функции, в том числе
после вызывающего кода; поддерживается рекурсия. Стандартной `libc` нет.

### Встроенный API

Имена и порядок аргументов соответствуют полям `kv_api_t` в `include/kvapp.h`:

* Графика: `width`, `height`, `rgb`, `clear`, `pixel`, `fill`, `rect`, `line`,
  `text`, `text_width`, `status`.
* Время/звук: `ticks`, `hz`, `seconds`, `delta_ms`, `clock`, `beep`.
* Память/строки: `alloc`, `release`, `mem_set`, `mem_copy`, `str_len`,
  `str_cmp`, `str_copy`, `format`.
* Файлы KvFS: `file_read`, `file_write`, `file_delete`, `file_list`, `file_exists`.
* Остальное: `random`, `log`, `lang` (0 — английский, 1 — русский).

Например, `text(x, y, "UTF-8 text", foreground, -1)` рисует текст с прозрачным
фоном. `rgb(r,g,b)` создаёт цвет в формате текущего видеорежима.
`format(buffer, size, "Count: %d", value)` форматирует строку в заранее
выделенный буфер. Буфер можно получить через `alloc(64)` и вернуть `release`.

## Поддерживаемое подмножество C

* 32-битный `int`, знаковый `char`, `void`, указатели; `const` распознаётся,
  но его запреты на запись не проверяются. Арифметика целых — знаковая.
* Глобальные переменные с числовым/строковым литералом или нулевой
  инициализацией; локальные переменные, параметры, объявления через запятую.
* Именованные параметры, определения и прототипы функций.
* `if/else`, `while`, `for`, `return`, `break`, `continue`, блоки.
* `+ - * / %`, сравнения, `& | ^ ~ << >>`, `! && ||`, присваивание,
  `+= -= *= /= %=`, префиксные и постфиксные `++ --`.
* Адрес `&variable`, разыменование `*pointer`, индексирование `pointer[i]`,
  арифметика указателей, одномерные массивы фиксированного размера и `sizeof`.
* Строковые и символьные литералы, escape-последовательности `\n \r \t \0
  \\ \" \'`, комментарии `//` и `/* ... */`.

**Это не полный ISO C и не GCC/TinyCC.** Нет полного препроцессора,
`union/enum`, `static/extern`, `unsigned/long`, чисел с плавающей точкой,
VLA/многомерных массивов, приведений типов, `switch`, `do/while`,
оператора `?:`, указателей на функции, внешних библиотек и объектных файлов.
Проверка типов ограничена; компилятор не является статическим анализатором.
Примеры существующего внешнего SDK с `sys->...` напрямую не собираются.
Для них остаётся обычная сборка GCC через `sdk/Makefile` на компьютере.

### Массивы и sizeof — M5.1, development

`int values[8];`, `char buffer[64];`, `int *slots[4];` разрешены глобально и
локально. Размер — положительный целочисленный **литерал**, в пределах прежних
бюджетов данных/стека. Пока нет VLA, пропущенного размера, выражения вместо
литерала, многомерных массивов и инициализаторов массивов. Глобальные массивы
обнулены, локальные не инициализированы. В выражениях массив превращается
в указатель на элемент; параметры объявляйте `int *p`, не `int p[8]`.
`&values[0]` работает; `&values` и указатели на целые массивы пока не поддержаны.
Индексы во время выполнения **не проверяются**.

`sizeof(int)`, `sizeof(char)`, `sizeof(int*)`, `sizeof values`, `sizeof(values[0])`,
строки и выражения: char = 1 байт, int = 4, указатель = 4/8 в зависимости от
архитектуры. Размер целого массива = число × размер элемента, без padding стека.
Выражение проверяется, но не исполняется: вызовы, присваивания и `++` внутри
`sizeof` не дают побочных эффектов. `sizeof(void)` — ошибка. Результат в этом
подмножестве — **int**, не стандартный size_t; поэтому `sizeof(sizeof(int))`
равен 4 и на x64. Глобальные инициализаторы пока только литеральные;
`sizeof(int[8])` и `int a[sizeof(int)]` пока не поддержаны. Бюджеты не повышались.

```c
void draw(void) {
    char buffer[64];
    format(buffer, sizeof buffer, "%d", sizeof(int*));
    clear(0);
    text(10, 20, buffer, -1, -1);
}
```

### Ограничения

Исходник компилятора: 16 000 байт; редактор: меньше 64 КиБ, до 120 байт
в строке; после 128 строк только предупреждение, отдельного лимита строк нет.
Код: 24 000 байт,
данные: 8 000 байт; файл вместе с заголовком укладывается в 32 КиБ.
До 8 аргументов, 256 символов (включая API), 128 записей локальных переменных,
512 байт (i386) или 1024 байта (x86-64) локального стека на функцию, 8 вложенных циклов, 24 уровня
вложенности парсера. Литерал — до 511 байт. При превышении — ошибка сборки.

## Безопасность

Как и другие `.kapp` KvantOS, результат работает в **ring 0**. Нативный код
не изолирован от ядра. Произвольный указатель, повреждение памяти,
глубокая рекурсия или бесконечный цикл могут повесить/уронить ОС.
Защита от некоторых исключений не превращает приложения в песочницу.
Сохраняйте исходники перед запуском экспериментов и используйте QEMU
с копией диска. Безопасность парсера не означает безопасность программы.

### 3.1.4-dev: русский ввод, поиск и статус сохранения

**EN/RU** в редакторе или **Alt+Shift** переключают ЙЦУКЕН. Caps/Shift,
ё/Ё/№ поддерживаются; Ctrl-сочетания, оболочка, ABI приложений и поля имён
сохраняют физическую латинскую раскладку. Язык интерфейса `lang ru/en` независим.

Кнопка **Поиск** (необязательно Ctrl+F; Ctrl+H открывает поле замены) даёт
**Назад / Далее / Заменить / Заменить всё**. Поиск буквальный, с учётом регистра,
переходит через край документа. Поля — до 127 байт UTF-8; Tab меняет поле,
Ctrl+U очищает его, Enter/Shift+Enter ищут вперёд/назад, Esc закрывает поиск.
«Заменить» сначала выделяет совпадение, если подходящего выделения ещё нет.
«Заменить всё» — одна отменяемая операция; при превышении 120 байт/строку
или общего бюджета текст и история не меняются. Regex/поиска без учёта регистра нет.

Нижняя строка постоянно показывает изменение документа и состояние текущей
версии в **RAM / KvFS**, включая отсутствие диска и ошибку записи. После
импорта появляется **На KvFS**: сохранение только по нажатию, без записи на
USB-источник. Без KvFS импорт остаётся временным. Ошибка диска не снимает `*`
и не переносит точку сохранения; возможный успех записи RAM отмечается отдельно.
Это не гарантия сохранности при отключении питания или внешней перезаписи файла.

### M5.2 development

Поддержаны ограниченные объектные `#define` и встроенные `#include` (M5.4 ниже).
Function-like макросы, условные директивы, переопределение, переносы и #/## дают ошибку.
До 32 определений, 255 байт body, 8 уровней, 32000 байт раскрытого текста.
Исходный лимит 16000 байт сохранён. [Подробно](../docs/M5.2-PREPROCESSOR.ru.md).

### M5.3 development

Поддержаны структуры, поля `.`/`->`, forward/self pointers и top-level typedef.
Native layout учитывает alignment/tail padding. Нет копирования/инициализации
aggregate и передачи по значению, local/nested type definitions, bitfields,
union/casts. До 32 tags, 256 полей, 32 aliases.
[Границы и примеры](../docs/M5.3-TYPES.ru.md).

## Изолированный target (экспериментальный ABI4)

Переключатель мышью **ABI3/kernel ↔ ABI4/CPL3** выбирает формат следующей сборки.
По умолчанию ABI3 остаётся доверенным ring0-кодом. ABI4 запускается в private
CPL3 memory, без kernel function pointers; user-only adapter предоставляет
ограниченный знакомый API. Работают rect/text/line/status, private heap/strings/
format, ticks/hz/lang/delta и private file_read/write/delete/list/exists.
beep/log выдаются как compile error; readonly clock добавлен в M4.13, без опасного fallback.

Файлы здесь — **8 приватных RAM-файлов по 1024B**, не KvFS. Пользовательская
сборка/сохранение из Мастерской по-прежнему может явно сохранять исходник и
.kapp на KvFS; исполняемое ABI4-приложение этого права не получает. LINE endpoints
ограничены signed16, canvas≤4096²; 64 draw ops / 1024 UTF-8 text bytes на DRAW.
Строка TEXT≤127 bytes; STATUS≤95. Рисовать следует в draw/open callbacks;
ошибка graphics service снимает приложение. Heap 32KiB; sizeof/array access
не добавляет автоматических C bounds checks. i386 non-PAE не имеет NX.

CODE_MAX24000 / DATA_MAX8000 / source16000 сохранены. Отдельный output49152
вмещает adapter; legacy output32768 не расширялся. Подробности и проверки:
`docs/M4.10-ISOLATED-WORKSHOP.ru.md`, `M4.11-RESOURCE-FAILURES.ru.md`,
`M4.12-LINE-PRIVATE-LIST.ru.md`. Это не стабильный ABI4 release.


### M5.4: встроенные readonly заголовки

`#include <kvui.h>` или `#include "kvui.h"` доступны в обоих targets.
Это только whitelist в памяти, не чтение файлов. `kvui.h` включает `kvkeys.h`
(8 KV_KEY_* и KV_CHAR_W/H) и `kvtypes.h` (kv_int=int, kv_byte=char,
kv_point={int x;int y;}); добавляет KV_BG=0x182032, KV_FG=0xe6f0ff,
KV_TRANSPARENT=-1. Каждый заголовок подключается один раз за сборку.
Вместе они расходуют 13 из 32 обычных macro slots, 3 aliases и 1 struct tag.
Это не stdint.h/unsigned/полный libc; объявления функций API по-прежнему встроены.
Пути/escapes, macro filenames, произвольные disk/SDK заголовки запрещены.
Depth4, cycle/work/output guards; номера ошибок относятся к исходному редактору.
[Контракт и software proof](../docs/M5.4-VIRTUAL-HEADERS.ru.md).


### M4.13: readonly clock

`clock(&h,&m,&s)` работает в isolated target; nullable/aliased outputs разрешены.
Это cached readonly snapshot последнего штатного RTC read, не CMOS I/O из
syscall, не setters/date/timezone API. h0..23/m,s0..59. Новый adapter требует
caps127; invalid/unavailable result → exit35. Только beep/log ещё отклоняются.
[Контракт и software proof](../docs/M4.13-READONLY-CLOCK.ru.md).
