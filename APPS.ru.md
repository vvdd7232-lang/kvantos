## За пять минут: первое приложение

Создайте файл `sdk/apps/hello.c`:

```c
/* KAPP_NAME "Привет" */
#include "kvapp.h"

static const kv_api_t *sys;      /* таблица системных функций */
static int clicks = 0;

static void on_draw(void) {
    sys->clear(sys->rgb(240, 244, 250));
    sys->text(20, 20, "Привет, KvantOS!", sys->rgb(20, 30, 50), 0xFFFFFFFF);

    char buf[64];
    sys->format(buf, sizeof(buf), "Щелчков: %u", clicks);
    sys->text(20, 50, buf, sys->rgb(120, 130, 150), 0xFFFFFFFF);
}

static void on_click(kv_i32 x, kv_i32 y, kv_i32 button) {
    clicks++;
    sys->beep(880, 30);
}

static kv_app_t me = {
    .title    = "Привет",
    .width    = 300,
    .height   = 160,
    .on_draw  = on_draw,
    .on_click = on_click,
};

kv_app_t *kapp_main(const kv_api_t *api) {
    sys = api;
    return &me;
}
```

Соберите и положите на диск:

```bash
cd sdk
make                                    # получится build/hello.kapp
python3 mkdisk.py ../disk.img 64 build/hello.kapp
```

Запустите систему и откройте значок **«Программы»** (или клавиша **G**
в графическом режиме) — приложение будет в списке. Щелчок по строке
запускает его.

Это полноценная программа: 300×160 точек, свой обработчик мыши, звук.
Весит она около килобайта.

## Как всё устроено

Приложение KvantOS — это **плоский двоичный образ**, который ядро
загружает по фиксированному адресу и вызывает у него одну функцию.
Никакого ELF в рантайме, никаких динамических библиотек, никаких
таблиц перемещений.

```
   ┌─────────────────────────────────────────────┐
   │  Файл program.kapp на диске (KvFS)          │
   │  ┌────────────┬──────────────────────────┐  │
   │  │ заголовок  │  образ памяти            │  │
   │  │  64 байта  │  код + данные            │  │
   │  └────────────┴──────────────────────────┘  │
   └──────────────────┬──────────────────────────┘
                      │  1. читаем с диска
                      │  2. проверяем подпись и версию ABI
                      ▼
   ┌─────────────────────────────────────────────┐
   │  Память по адресу 0x00E00000 (14 МиБ)       │
   │  код + данные + обнулённый bss              │
   └──────────────────┬──────────────────────────┘
                      │  3. вызываем kapp_main(&api)
                      ▼
   ┌─────────────────────────────────────────────┐
   │  Приложение возвращает kv_app_t             │
   │  с обработчиками on_draw / on_key / …       │
   └──────────────────┬──────────────────────────┘
                      │  4. оболочка зовёт их каждый кадр
                      ▼
              окно на рабочем столе
```

### Почему фиксированный адрес

Программа собирается сразу под адрес `0x00E00000`, поэтому ядру
не нужно ничего перемещать — достаточно скопировать байты и
передать управление. Плата за простоту: **одновременно работает
одно приложение**. Для системы такого размера это честный размен;
запуск второго закрывает первое.

### В каком кольце работает приложение

В **кольце ядра (ring 0)**. Это сознательное решение: приложение
получает прямой доступ к функциям системы без накладных расходов
на переключение колец, а ABI остаётся простым — обычные вызовы
функций через таблицу указателей.

Обратная сторона — приложение технически может испортить систему.
Поэтому вокруг каждого входа в программу стоит **страховочная
сетка**: если внутри приложения происходит исключение процессора
(обращение по неверному адресу, деление на ноль, неверная
инструкция), ядро не уходит в панику, а снимает виновника и
возвращается в оболочку. В окне появится «Приложение не
загружено» и причина сбоя.

Проверено на практике: приложение, пишущее по нулевому адресу,
закрывается, а система продолжает работать — счётчик кадров идёт,
оболочка отвечает на клавиши.

Нулевая страница памяти намеренно оставлена неотображённой, чтобы
разыменование `NULL` давало честное исключение, а не портило
таблицу прерываний молча.

## Формат файла .kapp

Файл состоит из 64-байтного заголовка и образа памяти. Все числа —
little-endian.

| Смещение | Размер | Поле | Описание |
|---|---|---|---|
| 0 | 4 | `magic` | Всегда `KAPP` |
| 4 | 2 | `version` | Версия формата, сейчас 1 |
| 6 | 2 | `header_size` | Размер заголовка, 64 |
| 8 | 4 | `api_version` | Версия ABI, под которую собрано |
| 12 | 4 | `flags` | 1 — оконное приложение |
| 16 | 4 | `load_base` | Адрес загрузки, обязан быть `0x00E00000` |
| 20 | 4 | `entry` | Абсолютный адрес `kapp_main` |
| 24 | 4 | `code_size` | Сколько байт читать из файла |
| 28 | 4 | `bss_size` | Сколько байт обнулить следом |
| 32 | 32 | `name` | Название для рабочего стола, UTF-8 |

Ограничения:

* код + bss — не больше **2 МиБ**;
* точка входа обязана попадать внутрь образа;
* при несовпадении `api_version` ядро откажется запускать файл и
  честно скажет, какая версия нужна.

Заголовок формирует `sdk/mkkapp.py` — вручную его собирать не нужно.

## Жизненный цикл приложения

```
   запуск (щелчок в «Программах»)
        │
        ├─► kapp_main(api)     один раз. Сохраните api и верните kv_app_t
        │
        ├─► on_open()          один раз, окно уже создано
        │
        │   ┌──────────── каждый кадр, пока окно открыто ──────────┐
        ├──►│  on_tick()   расчёты, анимация, опрос времени        │
        │   │  on_draw()   рисование                               │
        │   └──────────────────────────────────────────────────────┘
        │
        ├─► on_key(код)        когда окно активно и нажата клавиша
        ├─► on_click(x,y,кн)   щелчок внутри клиентской области
        │
        └─► on_close()         окно закрывают
```

Любой обработчик можно не задавать — оставьте поле нулевым.

**Важно:** структура `kv_app_t`, которую возвращает `kapp_main`,
обязана жить всё время работы программы. Объявляйте её `static`,
иначе вернёте указатель на исчезнувшую локальную переменную.

Кадр рисуется целиком заново. Фон окна ядро заливает само, но
если приложение не вызовет `clear()`, поверх него останется
предыдущий кадр — обычно это и нужно для анимации.

## Справочник системных функций

Всё, что приложение может попросить у системы, лежит в структуре
`kv_api_t`. Указатель на неё приходит в `kapp_main` — сохраните его
в глобальной переменной.

Координаты **всегда** отсчитываются от левого верхнего угла
клиентской области окна. Выход за границы обрезается ядром:
испортить чужое окно или панель задач невозможно.

### Размеры холста

| Функция | Описание |
|---|---|
| `kv_i32 width(void)` | Ширина клиентской области в пикселях |
| `kv_i32 height(void)` | Высота клиентской области |

Размер может отличаться от запрошенного в `kv_app_t`, если окно
не поместилось на экран. **Не кэшируйте эти значения** — спрашивайте
каждый кадр.

### Рисование

| Функция | Описание |
|---|---|
| `kv_u32 rgb(r, g, b)` | Собрать цвет из составляющих 0…255 |
| `void clear(color)` | Залить всё окно |
| `void pixel(x, y, color)` | Одна точка |
| `void fill(x, y, w, h, color)` | Закрашенный прямоугольник |
| `void rect(x, y, w, h, color)` | Рамка толщиной 1 |
| `void line(x0, y0, x1, y1, color)` | Отрезок |
| `void text(x, y, s, fg, bg)` | Строка UTF-8, кириллица допустима |
| `kv_i32 text_width(s)` | Ширина строки в пикселях |

Для прозрачного фона текста передайте `bg = 0xFFFFFFFF`.

Знакоместо шрифта — 8×16 точек, константы `KV_CHAR_W` и `KV_CHAR_H`.
Переноса строк нет: `\n` внутри строки не обрабатывается, разбивайте
текст сами.

### Строка состояния

| Функция | Описание |
|---|---|
| `void status(s)` | Текст в строке внизу окна |

Строку рисует система, приложению не нужно оставлять под неё место.

### Память

| Функция | Описание |
|---|---|
| `void *alloc(size)` | Выделить память в куче ядра |
| `void release(p)` | Освободить |

Куча общая с ядром, 10 МиБ. Освобождайте, что взяли: при выгрузке
приложения память автоматически не возвращается.

Небольшие буферы проще держать в статических массивах — они попадут
в bss, который ядро обнулит само.

### Время и звук

| Функция | Описание |
|---|---|
| `kv_u32 ticks(void)` | Тиков таймера с загрузки |
| `kv_u32 hz(void)` | Частота таймера (сейчас 1000) |
| `kv_u32 seconds(void)` | Секунд с загрузки |
| `void clock(&h, &m, &s)` | Часы реального времени |
| `void beep(freq, ms)` | Звук через PC-спикер, не дольше 1 с |

Тик равен миллисекунде, но **не полагайтесь на это** — спрашивайте
`hz()`. Именно так устроена анимация в примере «Заметки»:
`(ticks() - mark) / (hz() / 2)` даёт полусекундные интервалы
независимо от настроек таймера.

### Строки и память

Стандартной библиотеки у приложения нет, поэтому основное — в ABI:

| Функция | Описание |
|---|---|
| `void *mem_set(d, c, n)` | Заполнить байтом |
| `void *mem_copy(d, s, n)` | Скопировать |
| `kv_u32 str_len(s)` | Длина строки в байтах |
| `kv_i32 str_cmp(a, b)` | Сравнить |
| `void str_copy(d, s, max)` | Скопировать с ограничением |
| `void format(buf, size, fmt, …)` | Собрать строку |

`format` понимает `%d`, `%u`, `%x`, `%s`, `%c`, `%%` и ширину с
нулями (`%08x`). **Левого выравнивания (`%-10s`) нет** — дополняйте
пробелами вручную.

### Прочее

| Функция | Описание |
|---|---|
| `kv_u32 random(void)` | Псевдослучайное число |
| `void log(s)` | Строка в окно «Терминал» |
| `kv_i32 lang(void)` | Текущий язык интерфейса: 0 английский, 1 русский |

`log` — основной способ отладки, см. ниже.

## Клавиатура и мышь

### Клавиши

Обработчик `on_key(kv_i32 key)` получает:

* обычные символы — кодом ASCII/CP866 (`'a'`, `'5'`, `' '`);
* **Ctrl+буква** — кодами 1…26 (Ctrl+A = 1, Ctrl+S = 19, Ctrl+L = 12);
* специальные клавиши — значениями выше 255:

| Константа | Клавиша |
|---|---|
| `KV_KEY_UP` | Стрелка вверх |
| `KV_KEY_DOWN` | Стрелка вниз |
| `KV_KEY_LEFT` | Стрелка влево |
| `KV_KEY_RIGHT` | Стрелка вправо |
| `KV_KEY_ENTER` | Enter (это `'\n'`) |
| `KV_KEY_BKSP` | Backspace (это 8) |
| `KV_KEY_TAB` | Tab (это 9) |

**Esc до приложения не доходит** — эта клавиша закрывает окно.
Так из зависшей программы всегда можно выйти.

### Мышь

`on_click(x, y, button)` вызывается при нажатии внутри клиентской
области. Координаты уже пересчитаны относительно окна. `button`
равен 1 для левой кнопки.

Отслеживания перемещения без нажатия сейчас нет.

## Работа с файлами

Файлы лежат на диске в файловой системе KvFS и **переживают
перезагрузку**.

| Функция | Возвращает |
|---|---|
| `file_read(name, buf, max)` | Число прочитанных байт или код ошибки |
| `file_write(name, buf, size)` | 0 при успехе |
| `file_delete(name)` | 0 при успехе |
| `file_list(index, name40, &size)` | 0, пока файлы не кончились |
| `file_exists(name)` | 1, если файл есть |

Ограничения KvFS: **64 файла**, имя до **39 байт**, файл занимает
непрерывную цепочку секторов.

Типичный приём — прочитать настройки при запуске и записать при
закрытии:

```c
static char buf[256];

static void on_open(void) {
    kv_i32 got = sys->file_read("myapp.cfg", buf, sizeof(buf) - 1);
    if (got > 0) { buf[got] = 0; /* разобрать */ }
}

static void on_close(void) {
    sys->file_write("myapp.cfg", buf, sys->str_len(buf));
}
```

Если диска в системе нет, функции вернут ошибку — проверяйте
результат и не считайте запись гарантированной.

## Язык интерфейса

Система по умолчанию английская и переключается на русский во время
работы, поэтому приложениям стоит следовать за ней. ABI даёт две вещи:

```c
kv_i32 lang(void);              /* 0 = английский, 1 = русский */
KV_T(sys, "Save", "Сохранить")  /* выбирает строку для текущего языка */
```

`KV_T` — макрос поверх `lang()`, стоит одно сравнение:

```c
sys->text(20, 20, KV_T(sys, "Score", "Счёт"), fg, 0xFFFFFFFF);
```

Особый случай — заголовок окна: `kv_app_t` обязана быть `static`, а в
статическом инициализаторе вызов функции недопустим. Присваивайте
локализованный заголовок в `kapp_main`:

```c
kv_app_t *kapp_main(const kv_api_t *api) {
    sys = api;
    me.title = KV_T(api, "Clock", "Часы");
    return &me;
}
```

Все три примера в комплекте сделаны именно так — берите за образец.

## Сборка

### Что нужно

`gcc` с поддержкой 32-битных целей (`gcc-multilib`), `ld`, `python3`.
Те же инструменты, что и для сборки самой ОС.

### Обычный путь

Положите свой `.c` в `sdk/apps/` и выполните:

```bash
cd sdk
make
```

Makefile соберёт **все** файлы из `apps/`, каждый в отдельное
приложение, и разложит результат в `sdk/build/` и `release/apps/`.

Название для рабочего стола берётся из комментария в первых строках:

```c
/* KAPP_NAME "Моя программа" */
```

### Вручную

```bash
gcc -m32 -march=i586 -std=gnu11 -ffreestanding -fno-builtin \
    -fno-stack-protector -fno-pic -fno-pie -nostdlib -nostdinc \
    -Wall -Wextra -O2 -I../include -isystem $(gcc -m32 -print-file-name=include) \
    -c apps/hello.c -o build/hello.o

ld -m elf_i386 -T kapp.ld -nostdlib -o build/hello.elf build/hello.o

python3 mkkapp.py build/hello.elf build/hello.kapp "Привет"
```

Флаги важны все:

* `-ffreestanding -nostdlib -nostdinc` — libc нет и не будет;
* `-fno-pic -fno-pie` — код собирается под фиксированный адрес;
* `-T kapp.ld` — размещение по `0x00E00000` и метки границ образа;
* `-m32 -march=i586` — 32 бита, никаких SSE.

Предупреждение компоновщика `LOAD segment with RWX permissions`
нормально: у нас нет разделения прав на страницы.

## Установка на систему

Четыре способа. **Первый — основной**, он работает везде, включая
VMware, VirtualBox и настоящее железо, и не требует диска.

### 1. Вложить приложение в загрузочный образ (рекомендуется)

```bash
./sdk/addapp.sh моя_программа.kapp
```

Скрипт кладёт `.kapp` внутрь ISO, прописывает его в меню загрузчика
и пересобирает образы. Программа окажется в системе **сразу после
загрузки** — диск, сеть и флешка не нужны.

Дальше подключите `release/kvantos.iso` к виртуальной машине или
запишите на болванку. В системе: `guimenu` → клавиша **G** → ваша
программа в списке.

Так это устроено: GRUB загружает `.kapp` в память как модуль
Multiboot и передаёт ядру их список; ядро кладёт файлы в ramfs.
Запускать программы можно прямо оттуда, установка на диск не
обязательна — она нужна лишь для того, чтобы приложение могло
**сохранять** свои файлы.

Остальные способы — для случаев, когда диск уже есть.

### 2. Сразу в образ диска (для QEMU)

```bash
python3 sdk/mkdisk.py disk.img 64 sdk/build/clock.kapp sdk/build/notes.kapp
qemu-system-i386 -cdrom release/kvantos.iso -hda disk.img -m 256
```

Первый запуск создаёт образ на 64 МиБ с готовой файловой системой.
Приложения будут в списке сразу после загрузки.

Добавить программу в существующий образ:

```bash
python3 sdk/mkdisk.py --add disk.img sdk/build/hello.kapp
python3 sdk/mkdisk.py --list disk.img     # посмотреть содержимое
```

### 3. Из самой системы

Если диск ещё не размечен, сделайте это один раз:

```
kvant:/$ format
```

Либо кнопкой **«Разметить диск»** в окне «Программы». Дальше файл
из ramfs переносится на диск:

```
kvant:/$ install hello.kapp
kvant:/$ apps
```

Запишите ISO на диск или флешку, загрузитесь, выполните `format`
(**все данные на диске будут стёрты**), затем ставьте приложения.

## Что нельзя делать

Приложение работает в кольце ядра, поэтому запреты держатся на
договорённости, а не на аппаратной защите. Нарушите — система
снимет программу, но лучше до этого не доводить.

**Нельзя:**

* **обращаться к памяти вне своего образа и кучи.** Всё, что
  нужно, доступно через `kv_api_t`;
* **зацикливаться в обработчике.** Оболочка однопоточная: пока
  `on_draw` не вернулся, система не рисует кадры и не отвечает.
  Долгую работу разбивайте на части по кадрам;
* **вызывать функции ядра по имени.** Их адреса меняются от сборки
  к сборке. Только через таблицу;
* **рассчитывать на libc.** Ни `printf`, ни `malloc`, ни `strcpy`
  нет. Есть аналоги в ABI;
* **использовать числа с плавающей точкой.** FPU не инициализирован,
  а `-march=i586` не даёт SSE. Считайте в целых, как в примере
  «Часы» — там таблица синусов на целых числах;
* **делить 64-битные числа.** Это тянет `__udivdi3` из libgcc,
  которой при `-nostdlib` нет: получите ошибку компоновки.
  Приводите к 32 битам;
* **хранить состояние между запусками в памяти.** При выгрузке
  образ затирается. Пишите в файл.

**Можно:**

* держать сколько угодно статических данных (они лягут в bss);
* выделять память через `alloc`;
* читать и писать файлы;
* играть звуком, спрашивать время, писать в журнал.

## Отладка

Аппаратного отладчика для приложений нет, поэтому основной приём —
вывод в журнал:

```c
sys->log("сюда дошли");

char buf[64];
sys->format(buf, sizeof(buf), "x=%d, len=%u", x, len);
sys->log(buf);
```

Строки видны в окне **«Терминал»** графической оболочки.

Второй приём — рисовать отладочные данные прямо в окне: значения
переменных, границы областей, координаты щелчков. Это быстрее, чем
гадать.

Если приложение падает, ядро покажет причину в окне: «обращение к
памяти по адресу 0x…», «Divide by zero» и тому подобное. Причина
пишется по-английски, потому что берётся из таблицы исключений
процессора.

Частые причины сбоя:

| Симптом | Обычная причина |
|---|---|
| Сбой сразу при запуске | `kapp_main` вернула не-статическую структуру |
| «обращение к памяти по адресу 0x0» | Разыменован `NULL` |
| Ошибка компоновки `undefined reference` | Использована функция libc |
| `__udivdi3` при сборке | Деление 64-битных чисел |
| Окно пустое | Не задан `on_draw` или он ничего не рисует |
| Не приходят клавиши | Окно не активно, либо это Esc |

## Примеры

В комплекте два готовых приложения с подробными комментариями.

### `sdk/apps/clock.c` — «Часы»

Аналоговый циферблат со стрелками и цифровым временем.
Показывает:

* рисование примитивами (`line`, `fill`, `pixel`);
* тригонометрию **без чисел с плавающей точкой** — таблица синусов
  на целых, умноженная на 1024;
* чтение часов реального времени;
* обработку клавиш и щелчков;
* переключение темы.

Клавиши: **S** — секундная стрелка, **D** — тёмная тема, **B** — сигнал.

### `sdk/apps/snake.c` — «Змейка»

Игра: змейка ползает по сетке, ест еду, растёт. Показывает
**анимацию по времени** — движение через `on_tick` с шагом
`hz() / 6`, независимо от частоты кадров.

Клавиши: **стрелки** — поворот, **пробел** — начать заново.

### `sdk/apps/notes.c` — «Заметки»

Текстовый редактор, хранящий заметку на диске. Показывает:

* ввод текста с клавиатуры и мигающий курсор;
* перенос строк по ширине окна;
* собственные кнопки и попадание щелчком;
* **сохранение и чтение файла** — заметка переживает перезагрузку.

Клавиши: **Ctrl+S** — сохранить, **Ctrl+L** — перечитать с диска.

## Приложение: устройство KvFS

Знать это, чтобы писать приложения, не обязательно, но полезно, если
захотите работать с образом диска снаружи.

```
   сектор 0        суперблок: подпись KVFS, версия, счётчики
   секторы 1…8     каталог: 64 записи по 64 байта
   секторы 9…      данные, непрерывными цепочками
```

Запись каталога: имя (40 байт) + начальный сектор + число секторов
+ размер + флаги (1 — занята, 2 — исполняемый файл) + резерв.

Файл занимает непрерывный участок; при удалении остаётся дыра,
новый файл ищется по принципу «первый подходящий промежуток».
Фрагментации нет — это упрощает и ядро, и утилиты.

Размер записи проверяется на этапе компиляции (`_Static_assert`),
чтобы ядро и `sdk/mkdisk.py` не разошлись в раскладке.
